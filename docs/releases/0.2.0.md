# Tsukai 0.2.0

Tsukai 0.2.0 publishes the post-M5.5 public contract: the resident AgentRun owner and every surface merged through M5.5. `tsukai@0.1.0` predates all of it. This is the release that M6 (Mottainai adoption, #17) is meant to consume.

## Included surfaces

Everything in 0.1.0, plus:

- **M1a:** Pi RPC integration certified against the published `@earendil-works/pi-coding-agent@0.99.1` artifact (`SUPPORTED_PI_VERSION`, `SUPPORTED_PI_REVISION`), with the direct certification runner kept in `tsukai/testing`.
- **M1b:** Jinushi-owned production execution (`createJinushiClient`, `createJinushiPiExecutionPort`), with retry-safe submission and control identities.
- **M2:** the resident local owner (`startResidentOwner`, `connectOwner`, `tsukai owner serve`), a durable registry and journal (`createFileDurableStore`), local IPC, and restart reconciliation with explicit uncertainty and gaps. The owner client exposes `create`, `get`, `list`, `children`, `wait`, `cancel`, `result`, `events`, and `eventsPage`.
- **M3:** scoped agent-facing control (`connectAgent`: `agent_spawn`, `agent_status`, `agent_wait`, `agent_result`, `agent_cancel`), plus operator `grantAgentControl` and `revokeAgentControl`.
- **M4:** operator observation projections (`collectLiveProjection`, `projectReplay`, `renderOperatorProjection`) and `tsukai observe` / `tsukai replay`.
- **M5:** capability-aware multi-harness adapters (`createHarnessRuntime`, `createPiHarnessAdapter`, `createClaudeCodeHarnessAdapter`, `createJinushiClaudeCodeExecutionPort`), `HarnessCapabilities`, `runs.capabilities`, and capability-checked `steer`/`followUp` (`HarnessCapabilityError`).
- **M5.5:** admitted immutable execution profiles (`ExecutionProfile`, `EffectiveExecutionProfile`, `ExecutionProfileError`, `executionProfileFingerprint`, `EXECUTION_PROFILE_SCHEMA_VERSION`, and `PI_`/`CLAUDE_CODE_EXECUTION_PROFILE_CAPABILITIES`).

Version selection: the changes since 0.1.0 add public API and do not remove any, and the package is pre-1.0. That makes this a minor release.

## Requirements

- Node.js 24 or newer.
- Production execution needs a running Jinushi supervisor and the certified Pi 0.99.1 (or Claude Code 2.1.285) executable. The mock runtime in `tsukai/testing` needs neither.

## Install

```bash
npm install tsukai@0.2.0
```

## Release verification

The same packed tarball is verified before publication:

- `pnpm run test:package` installs the packed tarball into a clean consumer outside the repository and imports only `tsukai` and `tsukai/testing`. It exercises:
  - the resident owner and client: `create`, `get`, `list`, `children`, `wait`, waiter abort, `cancel`, `result`, `events`, `eventsPage`, `status`, and restart;
  - scoped agent control;
  - live and historical observation projections;
  - harness capabilities and `steer` rejection;
  - an execution-profiled run over the owner IPC;
  - the CLI;
  - declarations, checked with `tsc`.
- `scripts/smoke-test.mjs` runs in the publish workflow against the exact release tarball. It checks the CLI version and the M2–M5.5 exports that M6 needs.

Publication happens through `.github/workflows/publish.yml`, the shared yohn-jp npm publish workflow with npm Trusted Publishing (OIDC). A published GitHub Release tagged `v0.2.0` triggers it. The workflow checks that the tag matches `package.json`, then typechecks, tests, packs, smoke-tests, and publishes that one tarball.
